# 01. Обзор проекта

## Что это

**Reporter for autotests** — внутренний веб-инструмент для команды QA/разработки, который собирает
результаты автоматических тестов от CI и показывает их в разрезе тестовых фаз, отчётов и каталога
тестов.

Приложение решает три задачи:

1. **Приём результатов** — автоматизация (Java/JUnit + Surefire и аналоги) отправляет по одному
   HTTP-запросу на каждый завершённый запуск теста.
2. **Организация** — результаты группируются по проекту (workspace), тестовой фазе (например,
   «Release 2.4.0») и отчёту (например, «Smoke tests» за конкретную дату).
3. **Анализ** — отчёт показывает статус каждого теста из каталога, а аналитика считает процент
   прохождения, ошибки, владельцев, длительности и качество обратной связи по падениям.

Ключевая особенность модели: **запуск не привязан к отчёту внешним ключом**. Отчёт — это окно дат,
и он показывает все запуски, чей интервал `[startDate, endDate]` пересекается с окном отчёта,
а также тесты каталога, для которых запусков не было (статус `no_run`). За счёт этого один и тот же
запуск может попасть в несколько отчётов, а создание отчёта не требует перезаписи данных.

## Предметная область

```text
Workspace (проект)
└── Phase (фаза тестирования: окружение + период)
    └── Report (отчёт: окно дат внутри фазы)
        └── (представление) строки = каталог тестов × последний запуск в окне

Workspace
├── AutomatedTest (каталог тестов, ключ — resultPath)
│   └── AutomatedTestEnvironment (в каких окружениях тест участвует)
└── TestResult (запуски, ключ связи — path + workspaceId + circuit)
```

## Глоссарий

| Термин | Значение |
| --- | --- |
| **Workspace** | Изолированное пространство проекта. Имя — канонизированный `projectName`, который присылает автоматизация. |
| **Phase** | Тестовая фаза: имя, окружение (`environment`), период `startedAt…endedAt` (даты). |
| **Report** | Отчёт внутри фазы: имя (уникально в фазе), окно `startDate…endDate`. |
| **AutomatedTest** | Запись каталога. Бизнес-ключ `resultPath` (обычно fully-qualified имя Java-класса теста). |
| **resultPath** | Путь результата — строка, по которой запуск сопоставляется с каталогом. |
| **TestResult** | Один запуск теста: `path`, статус, владелец, `circuit`, сообщение, интервал, теги. |
| **circuit / environment** | Окружение, в котором выполнялся запуск. Сравнивается с `Phase.environment` без учёта регистра (оба хранятся в нижнем регистре). |
| **Harvest («Собрать из запусков»)** | Регистрация в каталоге уникальных `path` из уже сохранённых запусков за период, опционально — только для одного окружения. |
| **Каталог** | Набор `AutomatedTest`, определяющий, какие тесты показываются в отчёте (включая `no_run`). |
| **no_run** | Вычисляемый статус: тест есть в каталоге и видим, но подходящего запуска в окне отчёта нет. |
| **Видимость (`visible`)** | Флаг каталога: скрытые тесты не попадают в отчёты, включая их запуски. |
| **Legacy import** | Разовый импорт старого localStorage-снимка (`phases/reports/results`) в БД. |

## Роли и сценарии

Роли условны: аутентификации в приложении нет, доступ определяется сетевым периметром.

### 1. CI отправляет запуски

```text
JUnit/Surefire → POST /api/results (application/x-www-form-urlencoded)
              → ResultsService.normalize()
              → WorkspacesService.findOrCreateByName(projectName)
              → INSERT TestResult
```

Один запуск — один запрос. Ошибки валидации возвращают `400`, успешный приём — `201` с `{ received, id, path, status, workspaceId, projectName }`.
Подробнее — [07-ingestion-and-import.md](07-ingestion-and-import.md).

### 2. QA создаёт фазу и отчёт

1. Выбирает workspace в сайдбаре (или создаёт новый).
2. Создаёт фазу: имя, окружение, период.
3. Внутри фазы создаёт отчёт: имя и окно дат (окно обязано лежать внутри периода фазы).
4. Открывает отчёт: видит каталог тестов, статусы, поиск, обратную связь по падениям.
5. При необходимости открывает аналитику отчёта или аналитику всей фазы (сравнение отчётов,
   матрица «тест × отчёт», тренды и гигиена данных).

### 3. Наполнение каталога

- **Harvest**: «Каталог тестов» → «Собрать из запусков» → выбор периода. В каталог попадают
  уникальные пути из запусков, отфильтрованные по `circuit` = окружение фазы.
- **Импорт JSON**: загрузка файла с массивом тестов (или `{ "tests": [...] }`), предпросмотр,
  затем bulk-upsert по `resultPath`.
- **Вручную**: `POST /api/tests`.

### 4. Анализ качества

Страница аналитики отчёта считает на клиенте:

- распределение статусов, процент прохождения, эффективный pass rate и покрытие;
- тесты по владельцам (pass rate, падения, skipped/no run, p90, флаки);
- p50/p90/p95/p99, гистограмму длительностей, box plot по наборам и топ-8 самых медленных кейсов;
- нормализованные подписи ошибок с долей от всех падений и Парето;
- stale green (отчёт `passed`, но последний запуск упал) и флаки/ретраи (`retryFixed`, `regressed`);
- «результаты анализа» (`failureReason`) и долю падений без анализа по владельцам;
- уникальные пары «причина + комментарий» (`failureReason` + `failureComment`).

Страница аналитики фазы (`/phase/:id/analytics`) получает готовый серверный агрегат: KPI фазы,
сравнение отчётов, тренд прохождения и покрытия, lifecycle тестов, возраст текущих падений и MTTR,
матрицу «тест × отчёт», подписи ошибок, владельцев, наборы и гигиену данных.

## Что важно понимать про поведение

- **Отчёт не хранит результаты.** Он вычисляется на лету из каталога и запусков. Удаление отчёта
  не удаляет запуски; удаление фазы удаляет её отчёты (каскад), но не запуски.
- **Каталог — фильтр отчёта.** Запуски без записи в каталоге в отчёт не попадают, пока путь не
  зарегистрирован через Harvest/импорт. (В интерфейсе есть ветка `не зарегистрирован`, но текущий
  API всегда возвращает только каталожные строки — см. [03-frontend.md](03-frontend.md#нюансы).)
- **Окружение — часть контракта.** Запуск с `circuit`, не совпадающим с окружением фазы, в отчёт
  этой фазы не попадёт.
- **Приоритет статуса.** Если в окне есть хотя бы один успешный запуск пути, в отчёте показывается
  `passed`, даже если более поздний запуск упал. Иначе берётся самый поздний запуск.
- **Идентификаторы — BigInt в БД, Number в JSON.** Преобразование выполняется глобально в
  `api/src/main.ts`; см. ограничение точности в [06-data-model.md](06-data-model.md#идентификаторы).
- **Аутентификации нет.** API нельзя публиковать в интернет; legacy-импорт дополнительно выключен
  по умолчанию.

## Ограничения текущей версии

- Нет ролей, аутентификации и авторизации.
- Нет фоновых задач и real-time-обновлений: данные загружаются по действию пользователя.
- Аналитика отчёта считается на клиенте по уже загруженным результатам; аналитика фазы —
  на сервере (`GET /phases/:id/analytics`).
- В сайдбаре есть заглушки «Тестовые наборы», «История запусков», «Настройки» (помечены «Скоро»).
- `dist/` в корне и `api/dist/` — артефакты сборки, в репозиторий не входят (`.gitignore`).
